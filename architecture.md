# netmon Architecture

This document describes how netmon is built, how data moves through it, and which technologies it uses. For installation and usage, see `README.md`.

## 1. Overview

netmon is a network usage monitor for Ubuntu (Linux). Its data is per user: each user has their own database. It can be installed for the current user (`install.sh`) or for all users (Debian package `netmon_1.0.0_all.deb`). It has two Python files:

| File | Role |
| --- | --- |
| `netmon.py` | Core module: reads kernel counters, stores usage in SQLite, runs the daily rollup, formats and prints reports. Also a standalone command-line tool. |
| `netmon_gui.py` | GTK 3 desktop app: summary page, charts page, settings dialog, autostart handling. Imports `netmon.py`. |

Supporting files:

| File | Role |
| --- | --- |
| `install.sh` | Per-user installer and uninstaller. Copies files, creates the launcher, menu entry, icon. |
| `assets/netmon.svg` | Application icon (256 x 256 SVG). |
| `README.md` | User guide: install, uninstall, usage. |
| `netmon_1.0.0_all.deb` | System-wide Debian package built from the same two Python files, the icon and the README. Section 9.1. |

netmon uses only the Python standard library (`sqlite3`, `argparse`, `datetime`, `os`, `json`, `re`, `math`, `tempfile`, `traceback`, `collections`) plus Ubuntu's GTK 3 Python bindings (`gi`) for the GUI.

## 2. Technology stack

| Layer | Technology | Where used |
| --- | --- | --- |
| Language | Python 3 (system interpreter `/usr/bin/python3`) | All code |
| Kernel data source | `/proc/net/dev` | `read_counters()` in `netmon.py` |
| Storage | SQLite 3 in WAL journal mode | `open_db()`, all queries |
| GUI toolkit | GTK 3 via PyGObject (`gi`, `python3-gi`, `gir1.2-gtk-3.0`) | `netmon_gui.py` |
| Drawing | Cairo (through GTK `DrawingArea`) | `paint_*` functions, `ChartArea` |
| Desktop integration | `.desktop` files (menu entry, autostart), hicolor icon theme, `GtkApplication` (single instance, Ctrl+Q accelerator) | `install.sh`, `NetmonApp` |
| Settings | JSON file `~/.config/netmon/settings.json` | `load_settings()`, `save_settings()` |
| Installer | Bash (`set -euo pipefail`), apt (optional, for GTK packages) | `install.sh` |
| Packaging | Debian package (`dpkg-deb`, format 2.0), dependencies on `python3`, `python3-gi`, `python3-gi-cairo`, `gir1.2-gtk-3.0` | `netmon_1.0.0_all.deb` (section 9.1) |

## 4. Process model

There is one long-running process when netmon is open or autostarted: the GUI process (`netmon_gui.py`).

- `NetmonApp` is a `Gtk.Application` with application ID `local.netmon.gui`. GTK guarantees one instance: starting netmon again activates the running instance, which brings its window forward.
- `do_startup()` calls `hold()`, so the application keeps running when the window is hidden. Closing the window only hides it (`_on_close_requested` returns True). Quit (menu or Ctrl+Q) calls `quit()`, which runs `do_shutdown()`.
- `do_shutdown()` calls `NetmonWindow.shutdown()`, which flushes pending samples and closes the database connection.
- Login start: the autostart entry runs `netmon_gui.py --background`. `main()` removes that argument before GTK sees the command line and passes `start_hidden=True` to `NetmonApp`. The first `do_activate()` then builds the window, so its timer keeps sampling, but does not call `show_window()`. Any later activation (the menu entry, or running `netmon` again) finds the window already built and shows it.
- If the collector lock is already held at login, `do_activate()` writes one line to stderr and quits. It does not show the "already running" dialog, because nobody asked for a window. Opened by hand, the dialog still appears.

The command-line tool `netmon.py` has three commands and runs its own process:

| Command | Behavior |
| --- | --- |
| `live` | Collects data every `--interval` seconds (default 1) and prints a live dashboard. |
| `collect` | Collects data silently. Used for background collection without the GUI. |
| `report` | Prints the usage summary and exits. Optional `--iface`. |

SIGTERM is turned into a clean exit (`sys.exit(0)`), so pending data is flushed.

## 5. Data flow

### 5.1 Collection (every second)

```
GLib timer (1 s)                          netmon.py Collector
---------------                           -------------------
NetmonWindow._tick()  ---- tick() ---->   read_counters()  reads /proc/net/dev
                                          skip virtual and tunnel ifaces
                                          (lo, docker, br-, veth, virbr, tun, tap, wg, tailscale)
                                          delta = current counter - previous counter
                                          counter went backwards -> delta = 0 (reset)
                                          pending[(minute, iface)] += delta
                                          returns (rx_rate, tx_rate) in bytes/s
```

- The timer is `GLib.timeout_add(1000, self._tick)`. It runs for the whole life of the process, even when the window is hidden.
- `minute` is the Unix time rounded down to the start of the minute.
- The collector keeps counts in memory (`pending`) and writes them in batches.

### 5.2 Flush to SQLite (every 10 seconds)

`Collector.tick()` calls `flush()` when `FLUSH_SECONDS` (10) have passed since the last flush. `flush()`:

1. Writes all non-zero pending rows with an upsert:
   `INSERT ... ON CONFLICT(minute, iface) DO UPDATE SET rx = rx + excluded.rx, tx = tx + excluded.tx`
2. Commits, then clears `pending`. If the write fails (for example the database is locked), the error is printed, the samples stay in `pending`, and the save is retried at the next flush. Nothing is raised, so the collector keeps running.
3. Calls `maybe_rollup()` (see section 6). Errors are printed to stderr and collection continues.

### 5.3 Display

- Summary page: `_refresh_view()` shows current speeds and session totals from the collector. `netmon.summary_rows()` runs period queries for Today, Yesterday, Last 7 days, Last 30 days. It refreshes every second while the window is visible.
- Charts page: `_refresh_realtime()` redraws the live 2-minute chart every second from the in-memory rate history (`REALTIME_SECONDS`), which is filled on every tick. `_refresh_charts()` reads the database and redraws the other charts. It runs when the page opens, and every 5 seconds (`CHART_REFRESH_SECONDS`) while the page is visible.

### 5.4 Chart data queries

All chart data comes from the `usage` table through three functions in `netmon_gui.py`:

| Function | Chart | Query shape |
| --- | --- | --- |
| `hourly_series(conn)` | Last 24 hours | `GROUP BY` local hour (`strftime('%Y-%m-%d %H', minute, 'unixepoch', 'localtime')`), sums rx and tx for the last 24 hour buckets. |
| `daily_series(conn, 30)` | Last 30 days | Same hourly grouping, then summed per local calendar day in Python. |
| `interfaces_today(conn)` | Network interfaces today | `GROUP BY iface` for rows since local midnight, sorted by total, top 8. |

Hourly grouping is done in SQLite, so time zones and DST follow the system settings. Rollup rows (section 6) look the same to these queries, because they are stored at the start of each hour.

## 5.4 Single collector lock

Only one process may collect into a database. Two collectors read the same kernel counters and would both add the same bytes, doubling the totals.

- `acquire_collector_lock(db)` takes an exclusive `flock` on `<db>.lock` and writes the owner's PID into it.
- `netmon.py live` and `collect` take the lock and exit with a message if it is held. `report` does not need it.
- The GUI takes the lock on start. If it is held, the GUI shows a dialog naming the PID and quits. A login start (`--background`) logs a line to stderr and quits without the dialog.
- The kernel drops the lock when the process exits, so a crash never leaves it stuck.

## 6. Daily rollup

### 6.1 Purpose

Per-minute rows grow quickly: one row per minute per interface, about 1,440 rows per interface per day. The rollup keeps the database small by replacing the finished days with one summed row per local hour.

### 6.2 Rules

- Runs at most once per local calendar day.
- Only touches rows with `minute` before today's local midnight. Today is never changed.
- Rewrites every finished day that still has minute rows. Normally that is only yesterday. If the machine was off for several days, the next run compacts all of them.
- One row per local hour and interface, so `report --iface` still works for finished days.
- Rows written by older versions use the interface name `*` (`ROLLUP_IFACE`) and hold the sum over all interfaces. They cannot be split by interface, so `report --iface` prints a note when such rows fall inside the 30-day window.

### 6.3 Steps

```
maybe_rollup(conn)                       called from Collector.flush()
  1. read meta: last_rollup_date
  2. if it equals today's date -> return 0            (already done today)
  3. rollup_past_days(conn)
       a. commit pending work
       b. BEGIN IMMEDIATE                              (lock out other writers)
       c. SELECT hour, SUM(rx), SUM(tx)
            FROM usage WHERE minute < today_start AND iface != '*'
            GROUP BY hour                              (the SQL that combines rows per hour)
       d. DELETE the minute rows that were summed      (same WHERE clause)
       e. INSERT hourly rows with iface '*'
            ON CONFLICT(minute, iface) DO UPDATE SET rx = rx + excluded.rx ...
       f. COMMIT.  On any error: ROLLBACK and re-raise.
  4. upsert meta: last_rollup_date = today's date    (only after success)
```

Why the upsert in step e: a late sample for a finished day can arrive after the rollup has run. It is added to that hour's row instead of causing a primary-key error.

Why the lock in step b: an outside writer (for example a manual `sqlite3` session) cannot change rows between the read in step c and the delete in step d. Netmon's own collectors are kept apart by the collector lock (section 5.4).

### 6.4 Tests performed

On a temporary database with two days of synthetic data, the rollup:

- Turned 1,440 minute rows into 24 hourly rows.
- Left the total download and upload unchanged.
- Kept today's rows.
- Did nothing on a second run on the same day.
- Merged a late sample into its hour.
- Ran again once on the next day.

## 7. Database schema

Database file: `~/.local/share/netmon/usage.db`. Opened with `open_db()`, which sets `PRAGMA journal_mode=WAL` and creates tables if they do not exist.

```sql
CREATE TABLE usage (
    minute   INTEGER NOT NULL,          -- Unix time, start of the minute (or of the hour for rollup rows)
    iface    TEXT    NOT NULL,          -- NIC name; '*' only in rows written before per-interface rollup
    rx_bytes INTEGER NOT NULL DEFAULT 0,
    tx_bytes INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (minute, iface)
);

CREATE TABLE meta (
    key   TEXT PRIMARY KEY,             -- currently only 'last_rollup_date'
    value TEXT NOT NULL                 -- ISO date, e.g. '2026-11-11'
);
```

Row types in `usage`:

| Row type | `minute` | `iface` | Written by |
| --- | --- | --- | --- |
| Per-minute sample | start of the minute | NIC name | `Collector.flush()` |
| Hourly rollup | start of the local hour | NIC name | `rollup_past_days()` |

Queries that read the table:

| Query | Location | Notes |
| --- | --- | --- |
| `period_totals(conn, start, end, iface)` | `netmon.py` | Sum for a time range, optional interface filter. |
| `summary_rows(conn, iface)` | `netmon.py` | Four period totals for the summary and the report. |
| `_hour_totals(conn, since)` | `netmon_gui.py` | Sum per local hour, all interfaces. |
| `interfaces_today(conn)` | `netmon_gui.py` | Sum per interface since midnight. |
| rollup SELECT and DELETE | `netmon.py` | Finished days only (`minute < today_start`, `iface != '*'`). |

## 8. Settings and autostart

- `load_settings()` returns `{}` if the file does not exist, `None` if it is unreadable or not a JSON object (in which case the app leaves the user's choices alone), or the parsed dict.
- `save_settings()` writes atomically: a temporary file is written, fsynced, then renamed over the target (`_atomic_write()`).
- `apply_first_run_defaults()` runs at startup. The first time only, it enables autostart and sets `defaults_applied: true`. Later choices are kept.
- Autostart is a `.desktop` file in `~/.config/autostart/`. Its `Exec=` line points to the installed copy of `netmon_gui.py` and ends with `--background` (`_launch_command(background=True)`, called from `desktop_entry()`).
- `autostart_enabled()` is true when the user file exists and does not contain the line `Hidden=true`.
- `set_autostart(False)` behaves differently depending on whether `/etc/xdg/autostart/netmon.desktop` exists (installed by the .deb):
  - No system entry: the user file is deleted.
  - System entry present: the user file is replaced with a `Hidden=true` entry. Deleting it would let the system entry start netmon again. The hidden file overrides the system entry, so autostart stays off.
- The Settings dialog has one switch, "Start when I log in". It calls `set_autostart()`. If the file cannot be written, an error dialog is shown and the switch is reset.

## 9. Installer (`install.sh`)

| Command | Steps |
| --- | --- |
| `./install.sh` | Check the GTK 3 bindings (offer to install with apt if missing). Copy the Python files and icon. Write the menu entry (`local.netmon.gui.desktop`). Link `~/.local/bin/netmon`. If the autostart entry exists, rewrite its `Exec=` line to the installed copy with `--background`. Refresh icon and desktop caches. |
| `./install.sh --uninstall` | Remove the program folder, icon, menu entry (including the old name), launcher link, autostart entry and settings file. The usage database is kept. |

Helper functions: `check_gtk`, `install_app`, `uninstall_app`, `exec_value`, `rewrite_exec`, `desktop_quote`, `refresh_caches`.

The installer runs only as the current user. The only step that needs sudo is the optional `apt-get install python3-gi gir1.2-gtk-3.0`.

### 9.1 Debian package (`netmon_1.0.0_all.deb`)

The package installs netmon for all users. Its files are listed in section 3.

- **Control:** package `netmon`, version `1.0.0`, architecture `all`. Depends on `python3`, `python3-gi`, `python3-gi-cairo`, `gir1.2-gtk-3.0`, so apt installs the GTK packages. The Maintainer field is a placeholder that must be changed before sharing the package.
- **Launcher:** `/usr/bin/netmon` runs the system Python on `/usr/lib/netmon/netmon_gui.py`. The GUI finds `netmon.py` next to itself.
- **Autostart:** `/etc/xdg/autostart/netmon.desktop` starts `netmon --background` at login for each user. A user can switch it off in Settings; see section 8 for how the hidden override works.
- **Scripts:** `postinst` and `postrm` refresh the icon cache and the desktop database. They do not touch user data.
- **Data:** each user's `~/.local/share/netmon/usage.db` is not part of the package. Removing the package keeps it.
- **Build:** `dpkg-deb --root-owner-group --build` on a staging tree. The package holds the same files as the repository, so rebuild after any code change.
- **Conflict with the per-user install:** a `~/.local` install (`install.sh`) has its own menu entry and `~/.local/bin/netmon`, and a user autostart entry. Remove it with `./install.sh --uninstall` before installing the package.

## 10. Error handling and safety

| Situation | Behavior |
| --- | --- |
| Counter goes backwards (driver reload, reboot) | That interface's delta is set to 0 for that sample. |
| Virtual or tunnel interface (`lo`, `docker*`, `br-*`, `veth*`, `virbr*`, `tun*`, `tap*`, `wg*`, `tailscale*`) | Ignored, to avoid counting the same traffic twice. A VPN's traffic is counted once, on the physical NIC it runs over. |
| Login start while the collector lock is held | One line to stderr, exit without a window or dialog. |
| Autostart switched off while `/etc/xdg` entry exists | Hidden user override written, so autostart stays off. |
| SQLite error during a timer tick | Traceback printed, timer keeps running, retried next second. |
| SQLite error during rollup | Rolled back, error printed, minute rows kept, retried on the next flush. |
| Settings file unreadable | Autostart and settings are left as they are; a message is printed. |
| Settings write fails | Error dialog shown; switch returns to its real state. |
| Window closed | Hidden, not destroyed; monitoring continues. |
| SIGTERM (for example `systemctl stop`) | Exits cleanly so pending samples are flushed. |

## 11. Known limitations

- Only the GUI and the `netmon.py` command-line tool write to the database. Running both at once is safe for writes but each keeps its own pending counts.
- Rows from before per-interface rollup (iface `*`) cannot be split by interface. `report --iface` says so.
- The database is per user, not system-wide.
- Charts show history only from the time netmon was first run, so the hourly and daily charts look sparse at the beginning.
- The GUI requires GNOME-style desktop integration (application menu, autostart via `.desktop` files). It has been designed for Ubuntu.
- Collection happens only while the process runs. If netmon is not running, traffic is not recorded.
- VPN and tunnel traffic is measured on the physical NIC, so the totals include the VPN's encryption overhead and no longer match the plain traffic inside the tunnel.
- The Debian package's autostart applies to every user, but the database is still per user. A user who has never logged in gets no data.

## 12. Glossary

| Term | Meaning |
| --- | --- |
| Counter | Cumulative bytes received or sent by a NIC since boot, read from `/proc/net/dev`. |
| Delta | Difference between two counter readings, the bytes transferred in one sample interval. |
| Pending | Deltas kept in memory until the next flush. |
| Flush | Writing pending rows to SQLite. |
| Rollup | Replacing finished days' per-minute rows with per-hour rows. |
| Rollup row | Hourly row holding one interface's total for one local hour. |
| WAL | SQLite write-ahead log mode. Lets the reader and writer work at the same time. |
| Upsert | `INSERT ... ON CONFLICT DO UPDATE`: insert a row or add to the existing one. |
| Autostart | `.desktop` file in `~/.config/autostart/` (or `/etc/xdg/autostart/` for all users) that starts netmon at login. |
| Hidden override | A user autostart entry with `Hidden=true`. It switches off a system-wide autostart entry with the same name. |
| Login start (`--background`) | Start mode in which netmon collects data but does not show the window. |
